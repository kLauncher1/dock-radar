## ⚡ Ключевые возможности (Highlights)

- **Развертывание в виде одного исполняемого файла**: Веб-панель встроена непосредственно в исполняемый файл Go с помощью директивы `//go:embed`. Нет необходимости в среде Node.js, внешних ресурсах или отдельном веб-сервере.
- **Ультранизкое потребление оперативной памяти**: Непрерывно работает с расходом **менее 15 МБ ОЗУ** благодаря ограниченным кольцевым буферам, что идеально подходит для недорогих VPS, Raspberry Pi и домашних лабораторий.
- **Адаптивная телеметрия eBPF на уровне ядра и поведенческая безопасность**: Трекер сокетов на чистой стандартной библиотеке и инспектор Linux `/proc/net/tcp`, измеряющие в реальном времени подключения TCP/UDP, пропускную способность в байтах и круговую задержку (RTT). Встроенный механизм безопасности отслеживает системные вызовы контейнеров и автоматически выявляет запуск непредвиденных оболочек (`execve`), повышение привилегий (`setuid`), инспекцию памяти (`ptrace`), доступ к конфиденциальным файлам хоста (`/etc/shadow`), несанкционированное использование сокета Docker и подключения к пулам майнинга, сопровождая это визуальным монитором потоков и лентой инцидентов.
- **Распределенное временное хранилище логов и выгрузка в S3**: Сжатие логов контейнеров в оперативной памяти в блоки gzip (`.gz`) с расчетом криптографических контрольных сумм SHA-256 и атомарной записью на диск. Фоновый асинхронный модуль передает блоки в S3-совместимое хранилище (AWS S3, MinIO, Cloudflare R2) с помощью подписи AWS SigV4 без внешних библиотек. Поддерживаются лимиты емкости диска, очистка по сроку давности и встроенный обозреватель фрагментов с прямой загрузкой.
- **Бесперебойный последовательный перезапуск и дренаж трафика (Zero-Downtime Rolling Restarts)**: Поэтапный перезапуск контейнеров по репликам, стекам Compose или группам меток. Включает плавный дренаж активных запросов с настраиваемым тайм-аутом и оповещением обратных прокси через вебхук, многоступенчатую проверку готовности (состояние Docker, healthcheck, HTTP-эндпоинты `/healthz`, период стабилизации) и автоматическую отмену операции при сбоях.
- **Динамический мультинодовый кластер и обнаружение Gossip**: Автоматическое обнаружение в локальной сети по протоколу UDP-широковещания (порт 9085) в связке с легковесным протоколом SWIM Gossip. Включает случайные прямые запросы ping/ack, косвенные вспомогательные запросы ($k=3$), таймеры подозрений, опровержение воплощений и децентрализованный консенсус работоспособности с отображением карточек серверов в веб-интерфейсе.
- **Предиктивный анализ аномалий и радар исчерпания памяти OOM**: Линейная регрессия методом наименьших квадратов (OLS) в реальном времени для расчета наклона насыщения памяти ($m$), точки пересечения ($c$) и динамического времени до исчерпания (TTE). Ранние оповещения через вебхук до срабатывания механизма OOM Killer ядра Linux, а также индикаторы обратного отсчета в панели управления.
- **Автономный механизм самовосстановления (Self-Healing)**: Автоматический запуск правил восстановления при аварийных завершениях из-за нехватки памяти (`exit 137`) или постоянном сбое служб, защищенный экспоненциальной задержкой с джиттером, барьером изоляции (Circuit Breaker) и метриками Prometheus.
- **Визуализатор топологии и стеков Docker Compose**: Автоматическая группировка контейнеров по меткам `com.docker.compose.project` с интерактивными графами зависимостей SVG. Определение уровней архитектуры (СУБД, кэш, очереди, шлюзы, воркеры) и управление полным жизненным циклом стека (перезапуск, остановка, пересоздание).
- **Интерактивный терминал контейнера в браузере (Exec)**: Полнодуплексный интерактивный shell-терминал через WebSocket (`/api/docker/exec`) с точной отрисовкой escape-последовательностей VT100 / ANSI (256 цветов), принудительным режимом «только для чтения» и автоотключением при бездействии.
- **Мультихостовая агентная сеть и централизованный агрегатор**: Мониторинг контейнеров, распределенных по множеству серверов. Динамическая регистрация узлов, проверка доступности, измерение задержки RTT и объединенная телеметрия.
- **Стандартный экспортер метрик Prometheus**: Нативный эндпоинт `/metrics`, передающий показатели хоста, контейнеров, узлов сети, алертов и аудита в стандартном формате Prometheus для интеграции с Grafana.
- **Пакетные операции с контейнерами**: Синхронизированные команды через интерфейс или API (`restart_all`, `stop_all`) и безопасное удаление неиспользуемых контейнеров (`prune`).
- **Потокобезопасный журнал аудита (Audit Trail)**: Кольцевой буфер емкостью до 2 000 записей, фиксирующий административные действия и события безопасности с выгрузкой в форматах NDJSON и JSON (`/api/audit/export`).
- **Автоматическое шифрование TLS**: Встроенный генератор сертификатов создает самоподписанные сертификаты ECDSA P-256 с расширением SAN для localhost и всех сетевых интерфейсов. Поддерживается подключение собственных сертификатов через флаги CLI и переменные среды.
- **Аутентификация по токену Bearer и модель доступа RBAC**: Разделение прав доступа на роли `admin` (полный контроль над контейнерами и настройками) и `viewer` (просмотр метрик и логов в режиме чтения) с проверкой токенов за постоянное время (`subtle.ConstantTimeCompare`) для защиты от тайминг-атак.
- **Автоматические оповещения через Webhook**: Мгновенная доставка уведомлений в Discord (с цветовым кодированием) и Slack при аварийном завершении, падении или циклическом перезапуске контейнеров.
- **Контроль частоты сбоев и дребезга (Flapping)**: Алгоритм скользящего окна фиксирует частые перезапуски контейнеров, предотвращая скрытую деградацию сервисов.
- **Мониторинг порогов загрузки хоста**: Настраиваемые лимиты потребления процессора и памяти с дедупликацией уведомлений и периодом паузы.
- **Потоковая передача логов в реальном времени**: Подключение по WebSocket RFC 6455 (`/api/docker/logs`) с демультиплексированием потоков stdout/stderr Docker и резервным получением моментальных снимков через REST JSON.
- **Контроль жизненного цикла через Docker Socket**: Опрос активных контейнеров и выполнение безопасных операций перезапуска и остановки с окном подтверждения.
- **Телеметрия хост-системы**: Мониторинг количества ядер CPU, активных горутин, выделенной оперативной памяти, циклов сборщика мусора (GC) и времени аптайма.
- **Мультиплатформенная матрица сборок**: Скомпилировано и протестировано для Linux (amd64, arm64), macOS (amd64, arm64 Apple Silicon) и Windows (amd64).

## 🚀 Быстрый старт (Quick Start)

### 1. Загрузка и запуск (Автономный бинарный файл)

```bash
# Клонирование репозитория
git clone https://github.com/kLauncher1/dock-radar.git
cd dock-radar

# Запуск напрямую через Go (порт HTTP по умолчанию: 9080)
go run .
```

Веб-консоль будет сразу доступна по адресу:
👉 **`http://localhost:9080`**

### 2. Запуск с TLS и авторизацией (Защищенный продакшн-режим)

```bash
# Включение автоматического TLS и задание токенов администратора и наблюдателя
go run . --tls --admin-token="my-super-secret-admin-token" --viewer-token="my-readonly-token"
```

Защищенная веб-консоль доступна по адресу:
👉 **`https://localhost:9080`**

### 3. Сборка единого исполняемого файла

```bash
# Компиляция компактного исполняемого файла без отладочных символов
go build -ldflags="-s -w" -o dock-radar .

# Просмотр параметров запуска
./dock-radar --help
```

### 4. Параметры конфигурации и переменные среды

| Флаг CLI | Переменная среды | По умолчанию | Описание |
| :--- | :--- | :--- | :--- |
| `--port` | `PORT` | `9080` | Порт TCP для прослушивания веб-панели и API |
| `--tls` | `DOCK_RADAR_TLS` | `false` | Включение защищенного режима HTTPS |
| `--tls-cert` | `DOCK_RADAR_TLS_CERT` | `""` | Путь к файлу сертификата TLS в формате PEM |
| `--tls-key` | `DOCK_RADAR_TLS_KEY` | `""` | Путь к файлу приватного ключа TLS в формате PEM |
| `--admin-token` | `DOCK_RADAR_ADMIN_TOKEN` | `""` | Токен Bearer с полными правами администратора |
| `--viewer-token` | `DOCK_RADAR_VIEWER_TOKEN`| `""` | Токен Bearer с правами только для чтения |
| `--allow-remote` | `DOCK_RADAR_ALLOW_REMOTE`| `false` | Разрешить внешние подключения без проверки loopback |
| `--nodes` | `DOCK_RADAR_NODES` | `""` | Список адресов удаленных узлов dock-radar (через запятую) |

| `--gossip-interval` | `DOCK_RADAR_GOSSIP_INTERVAL` | `5s` | Интервал проверки доступности протокола SWIM Gossip |
| `--version` | — | — | Вывести номер версии dock-radar и завершить работу |

### Гарантии безопасности (Security Guarantees)
- **Шифрование транспортного уровня (TLS)**: Генерация в памяти сертификатов ECDSA P-256 с валидацией SAN для всех сетевых интерфейсов хоста либо использование корпоративных сертификатов.
- **Аутентификация за постоянное время**: Сравнение токенов реализовано через `crypto/subtle.ConstantTimeCompare`, исключая утечки информации через тайминг-атаки.
- **Разграничение ролей по модели RBAC**: Интерфейсы чтения доступны ролям `viewer` и `admin`, а операции изменения состояния строго требуют привилегий `admin`.
- **Ограничение Loopback по умолчанию**: При отсутствии настроенных токенов эндпоинты управления доступны исключительно с локального интерфейса (`127.0.0.1`, `::1`, `localhost`).
- **Защита от CSRF и DNS Rebinding**: Проверка метаданных браузера (`Sec-Fetch-Site`) и заголовков `Origin`/`Referer` для блокировки межсайтовых атак.
- **Блокировка SSRF и доступа к метаданным**: Цели вебхуков проверяются на протоколы HTTP/HTTPS, очищаются от символов CRLF и защищены от обращения к адресам облачных метаданных (`169.254.169.254`, `metadata.google.internal`).
- **Валидация входящих параметров**: Идентификаторы и имена контейнеров проверяются по шаблону `^[a-zA-Z0-9][a-zA-Z0-9_.-]{0,127}$`, что исключает выход за пределы путей и инъекции в сокет.
- **Ограничение частоты запросов**: Алгоритм Token Bucket ограничивает вызовы команд управления до 5 операций с восполнением со скоростью 1 токен в секунду.

## 📡 Справочник API REST и WebSocket

| Эндпоинт | Метод / Протокол | Требуемая роль | Описание |
| :--- | :---: | :---: | :--- |
| `/metrics` | `GET` | `viewer` | Стандартный экспорт метрик Prometheus для сбора сервером Grafana |
| `/api/system` | `GET` | `viewer` | Имя хоста, ОС/архитектура, ядра CPU, горутины, выделенная память, GC и аптайм |
| `/api/docker` | `GET` | `viewer` | Статус демона Docker, количество запущенных контейнеров и их подробные параметры |
| `/api/docker/batch` | `POST` | `admin` | Пакетные операции: `restart_all`, `stop_all`, `prune` (`{"action":"restart_all","timeout":10}`) |
| `/api/docker/logs` | `WS` / `GET` | `viewer` | Потоковая трансляция логов по WebSocket или снимок в формате JSON (`?id=<id>&tail=100`) |
| `/api/docker/restart` | `POST` | `admin` | Безопасный перезапуск контейнера по ID или имени (`{"id":"<id>","timeout":10}`) |
| `/api/docker/stop` | `POST` | `admin` | Безопасная остановка запущенного контейнера (`{"id":"<id>","timeout":10}`) |
| `/api/healing/config` | `GET` / `POST` | `viewer` / `admin` | Запрос и обновление политик самовосстановления и правил исключения |
| `/api/healing/status` | `GET` | `viewer` | Текущие метрики восстановления, изолированные контейнеры и задержки |
| `/api/healing/history`| `GET` | `viewer` | Журнал недавних событий автоматического восстановления (`?limit=50`) |
| `/api/healing/reset`  | `POST` | `admin` | Сброс блокировки изоляции и обнуление счетчиков задержки для контейнера |
| `/api/nodes` | `GET` / `POST` / `DELETE` | `viewer` / `admin` | Список зарегистрированных узлов, подключение и отключение участников сети |
| `/api/nodes/heartbeat` | `POST` | `viewer` | Эндпоинт приема сигналов доступности и данных от удаленных агентов |
| `/api/cluster/summary` | `GET` | `viewer` | Сводные показатели кластера (активные узлы, загрузка процессора, памяти, контейнеры) |
| `/api/cluster/containers` | `GET` | `viewer` | Единый реестр контейнеров со всех узлов кластера (`?node_id=&state=`) |
| `/api/mesh/discovery` | `GET` / `POST` | `viewer` / `admin` | Статус локального поиска узлов и ручная отправка широковещательного пакета |
| `/api/mesh/gossip` | `GET` / `POST` | `viewer` / `none` | Статус участия в протоколе SWIM Gossip и прием входящих сообщений |
| `/api/audit/export` | `GET` | `viewer` | Экспорт журнала аудита в форматах NDJSON или JSON (`?format=ndjson&limit=2000`) |
| `/api/alerts/config` | `GET` / `POST` | `viewer` / `admin` | Настройка правил оповещений, адресов вебхуков и пороговых значений |
| `/api/alerts/events` | `GET` | `viewer` | Буфер недавних инцидентов и зафиксированных тревог (`?limit=50`) |
| `/api/alerts/test` | `POST` | `admin` | Немедленная отправка тестового оповещения в Discord или Slack |
| `/api/auth/status` | `GET` | `none` | Возвращает статус TLS, режим удаленного доступа и уровень текущих прав |
| `/api/auth/verify` | `POST` | `none` | Проверка переданного токена Bearer и возврат назначенной роли |
| `/` | `GET` | `none` | Предоставление встроенной веб-панели управления |
