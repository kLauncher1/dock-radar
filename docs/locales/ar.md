## ⚡ أبرز الميزات (Highlights)

- **نشر عبر ملف تنفيذي ثنائي واحد**: لوحة تحكم الويب مدمجة مباشرة في ملف Go الثنائي عبر تعليمة `//go:embed`. لا حاجة لبيئة Node.js أو موارد خارجية أو خوادم ويب منفصلة.
- **استهلاك ضئيل للغاية للذاكرة**: يعمل باستمرار بأقل من **15 ميجابايت من الذاكرة العشوائية (RAM)** باستخدام مخازن دائرية ذات سعة محددة، مما يجعله مثالياً لخوادم VPS منخفضة المواصفات و Raspberry Pi والمختبرات المنزلية.
- **تليمترية eBPF تكيفية ومحرك أمان سلوكي على مستوى النواة**: متتبع تدفق المقابس ومفتش Linux `/proc/net/tcp` بمكتبة قياسية بحتة لقياس اتصالات TCP/UDP ومعدل نقل البيانات والكمون ذهاباً وإياباً (RTT) لحظياً. يرصد محرك الأمان السلوكي استدعاءات نظام الحاويات بقواعد تلقائية لاكتشاف تنفيذ الأوامر غير المتوقع (`execve`) وتصعيد الصلاحيات (`setuid`) وفحص الذاكرة (`ptrace`) والوصول إلى ملفات النظام الحساسة (`/etc/shadow`) واستغلال مقبس Docker والاتصال بأحواض التعدين، مع مراقب تدفق مرئي وسجل مباشر للحوادث.
- **تخزين مؤقت موزع للسجلات وتفريغ إلى S3**: ضغط سجلات الحاويات في الذاكرة إلى كتل gzip (`.gz`) مع بصمات تشفير SHA-256 وكتابة ذرية على القرص. يقوم مفرغ خلفي غير متزامن بنقل الكتل إلى وحدات تخزين متوافقة مع S3 (AWS S3 و MinIO و Cloudflare R2) باستخدام موقع AWS SigV4 قياسي بدون مكتبات خارجية، مع إدارة سعة القرص والتنظيف التلقائي ومستكشف مخصص للتنزيل المباشر.
- **إعادة تشغيل تدريجية بدون توقف وتفريغ لحركة المرور (Zero-Downtime Rolling Restarts)**: جدولة إعادة التشغيل المتسلسلة للحاويات أو مكدسات Compose أو مجموعات التصنيفات. يتضمن تفريغاً سلساً للاتصالات النشطة مع مهل زمنية قابلة للتعديل وتنبيهات webhook للوكيل العكسي، وفحص جاهزية متعدد المراحل (حالة Docker، الفحص الصحي، نقاط `/healthz`)، مع إلغاء وتراجع تلقائي عند حدوث أخطاء متتالية.
- **شبكة عنقودية ديناميكية واكتشاف النظراء عبر Gossip**: اكتشاف تلقائي عبر بث UDP على الشبكة المحلية (منفذ 9085) مقترن ببروتوكول SWIM Gossip الخفيف. يدعم إشارات ping/ack العشوائية المباشرة، والمساعدة غير المباشرة ($k=3$)، ومؤقتات الاشتباه، وتوافق الآراء اللامركزي حول صحة العنقود المعروض في بطاقات لوحة التحكم.
- **اكتشاف تنبؤي للشذوذ ورادار استنفاد الذاكرة OOM**: تحليل انحدار خطي OLS في الوقت الفعلي لتوقع ميل تشبع الذاكرة ($m$) ونقطة التقاطع ($c$) والوقت الديناميكي المتبقي حتى النفاد (TTE). إرسال تنبيهات webhook مبكرة قبل أن يتدخل قاتل OOM في النواة لإيقاف الحاويات، مع عدادات تنازلية تفاعلية.
- **محرك إصلاح ذاتي مستقل (Self-Healing)**: تطبيق قواعد استرداد تلقائية للحاويات عند تعطلها بسبب نقص الذاكرة (`exit 137`) أو الدخول في حالات تذبذب غير مستقرة، مدعوماً بتراجع أسي مع تشويش (jitter) وقواطع حماية ومقاييس Prometheus.
- **مخطط تفاعلي لمكدسات Docker Compose**: تجميع تلقائي للحاويات وفقاً لتصنيف `com.docker.compose.project` مع رسوم بيانية SVG تفاعلية للتبعيات. تصنيف طبقات البنية (قواعد بيانات، ذاكرة مؤقتة، طوابير، بوابات، عمال) مع تحكم كامل بدورة حياة المكدس (إعادة تشغيل، إيقاف، إعادة إنشاء).
- **طرفية تحكم تفاعلية داخل المتصفح (Exec)**: طرفية أوامر تفاعلية كاملة الازدواج عبر WebSocket (`/api/docker/exec`) مع دعم تسلسلات الهروب VT100 / ANSI (256 لوناً)، وفرض سياسة القراءة فقط، وإنهاء الجلسات الخاملة تلقائياً.
- **شبكة وكلاء متعددة الخوادم ومجمع مركزي**: مراقبة الحاويات الموزعة عبر خوادم متعددة في الوقت الفعلي، مع دعم تسجيل العقد ديناميكياً وقياس زمن الاستجابة RTT وتوحيد التليمترية.
- **مصدّر مقاييس قياسي لـ Prometheus**: نقطة نهاية `/metrics` أصلية تعرض مقاييس الخادم المضيف والحاويات والعقد والتنبيهات وسجلات التدقيق بتنسيق Prometheus للربط مع Grafana.
- **إدارة العمليات المجمعة للحاويات**: تنفيذ أوامر متزامنة بنقرة واحدة أو عبر واجهة برمجة التطبيقات (`restart_all` و `stop_all`) مع تنظيف آمن للحاويات الخاملة (`prune`).
- **سجل تدقيق آمن للتزامن (Audit Trail)**: مخزن دائري يتسع لما يصل إلى 2,000 إجراء إداري وأمني مع تصدير بتنسيقي NDJSON و JSON (`/api/audit/export`).
- **تشفير نقل تلقائي (TLS)**: محرك شهادات ينشئ في الذاكرة شهادات ECDSA P-256 ذاتية التوقيع مع دعم أسماء SAN لعناوين localhost والواجهات الشبكية، مع دعم كامل للشهادات المخصصة عبر المعاملات ومتغيرات البيئة.
- **مصادقة برموز Bearer وتحكم في الوصول المستند للأدوار (RBAC)**: فصل دقيق بين دور المشرف `admin` (تحكم كامل وإدارة التنبيهات) ودور المشاهد `viewer` (قراءة المقاييس والسجلات فقط)، مع مقارنة الرموز بزمن ثابت لمنع هجمات التوقيت الجانبية.
- **تنبيهات Webhook المؤتمتة**: إرسال إشعارات فورية إلى Discord (رسائل منسقة ملونة) و Slack عند توقف الحاويات المفاجئ أو تعطلها أو دخولها في حلقات إعادة تشغيل.
- **كشف التذبذب وتكرار الأعطال (Flapping)**: مراقبة بنافذة منزلقة ترصد دورات إعادة التشغيل السريعة قبل حدوث انقطاع كامل في الخدمة.
- **مراقبة عتبات موارد الخادم**: تعيين حدود لاستهلاك المعالج والذاكرة مع منع تكرار التنبيهات وفترات تهدئة مبرمجة.
- **بث مباشر لسجلات الحاويات**: بث لحظي عبر بروتوكول RFC 6455 WebSocket (`/api/docker/logs`) مع فرز قنوات stdout/stderr لـ Docker وبديل REST JSON في حال تعذر الاتصال المباشر.
- **فحص مقبس Docker وإدارة دورة الحياة**: استعراض الحاويات النشطة وتوفير أزرار آمنة لإعادة التشغيل والإيقاف والحذف مع مربعات حوار للتأكيد.
- **تليمترية النظام المضيف**: قياس مستمر لأنوية المعالج، وخيوط goroutines، والذاكرة المحجوزة، ودورات جمع القمامة (GC)، وزمن التشغيل المستمر.
- **مصفوفة ملفات تنفيذية متعددة المنصات**: تم البناء والاختبار لأنظمة Linux (amd64, arm64) و macOS (amd64, arm64 Apple Silicon) و Windows (amd64).

## 🚀 البدء السريع (Quick Start)

### 1. التحميل والتشغيل (ملف تنفيذي مستقل)

```bash
# استنساخ المستودع
git clone https://github.com/kLauncher1/dock-radar.git
cd dock-radar

# التشغيل المباشر عبر Go (منفذ HTTP الافتراضي: 9080)
go run .
```

لوحة التحكم المدمجة ستكون متاحة فوراً عبر الرابط:
👉 **`http://localhost:9080`**

### 2. التشغيل مع تفعيل TLS والمصادقة (وضع الإنتاج الآمن)

```bash
# تفعيل TLS التلقائي وتعيين رموز الوصول للمشرف والمشاهد
go run . --tls --admin-token="my-super-secret-admin-token" --viewer-token="my-readonly-token"
```

رابط لوحة التحكم الآمنة:
👉 **`https://localhost:9080`**

### 3. بناء ملف تنفيذي واحد

```bash
# تجميع ملف تنفيذي مستقل ومجرد من رموز التصحيح
go build -ldflags="-s -w" -o dock-radar .

# استعراض تعليمات التشغيل
./dock-radar --help
```

### الضمانات الأمنية (Security Guarantees)
- **تشفير طبقة النقل (TLS)**: إنشاء شهادات ECDSA P-256 ذاتية التوقيع في الذاكرة مع أسماء SAN لكافة الواجهات أو دعم شهادات المؤسسات المخصصة.
- **مصادقة في زمن ثابت**: مطابقة الرموز بالدالة `crypto/subtle.ConstantTimeCompare` لتعطيل هجمات القنوات الجانبية المعتمدة على الفروق الزمنية.
- **تقسيم أدوار صارم (RBAC)**: نقاط الاستعلام مفتوحة للمشاهدين والمشرفين، في حين تتطلب عمليات التعديل والإيقاف والتشغيل صلاحية المشرف حصراً.
- **حصر الوصول المحلي افتراضياً**: في حال عدم تعيين رموز مصادقة، يتم قصر العمليات التعديلية على واجهات التكرار المحلي (`127.0.0.1` و `::1` و `localhost`).
- **حماية ضد هجمات CSRF و DNS Rebinding**: التحقق الإلزامي من ترويسات المتصفح الحديثة (`Sec-Fetch-Site`) وترويسات `Origin`/`Referer` لمنع الطلبات المتقاطعة غير الموثوقة.
- **منع SSRF وعزل خوادم البيانات الوصفية**: تلزم نقاط الويب بروتوكولات HTTP/HTTPS، وتتخلص من أحرف التحكم (CRLF)، وترفض صراحة الوصول إلى عناوين الميتاداتا السحابية (`169.254.169.254` و `metadata.google.internal`).
- **فحص حدود المعاملات**: تخضع جميع معرفات وأسماء الحاويات لفحص بنمط الحروف والأرقام `^[a-zA-Z0-9][a-zA-Z0-9_.-]{0,127}$` لمنع اختراق المسارات وحقن الأوامر.
- **تحديد معدل الطلبات (Rate Limiting)**: يحد خوارزم دلو الرموز استدعاءات التحكم في الحاويات إلى 5 عمليات مع إعادة تعبئة بمعدل رمز واحد في الثانية.

## 📡 مرجع واجهات برمجة التطبيقات (REST & WebSocket)

| نقطة الوصول | الطريقة / البروتوكول | الدور المطلوب | الوصف |
| :--- | :---: | :---: | :--- |
| `/metrics` | `GET` | `viewer` | مقاييس Prometheus القياسية لجمع البيانات وربطها مع Grafana |
| `/api/system` | `GET` | `viewer` | اسم الخادم، المنصة/المعمارية، الأنوية، الخيوط، الذاكرة (MB)، دورات GC ووقت التشغيل |
| `/api/docker` | `GET` | `viewer` | حالة اتصال Docker، تعداد الحاويات الكلي والنشط مع تفاصيلها |
| `/api/docker/batch` | `POST` | `admin` | إدارة مجمعة: `restart_all` و `stop_all` و `prune` (`{"action":"restart_all","timeout":10}`) |
| `/api/docker/logs` | `WS` / `GET` | `viewer` | بث مباشر للسجلات عبر WebSocket أو لقطة سريعة بتنسيق JSON (`?id=<id>&tail=100`) |
| `/api/docker/restart` | `POST` | `admin` | إعادة تشغيل آمنة لحاوية عبر المعرف أو الاسم (`{"id":"<id>","timeout":10}`) |
| `/api/docker/stop` | `POST` | `admin` | إيقاف آمن لحاوية قيد التشغيل (`{"id":"<id>","timeout":10}`) |
| `/api/healing/config` | `GET` / `POST` | `viewer` / `admin` | استعراض أو تحديث سياسات المعالجة الذاتية وهوامش التراجع والاستثناءات |
| `/api/healing/status` | `GET` | `viewer` | إحصائيات المعالجة والحاويات في الحجر وحالات التراجع |
| `/api/healing/history`| `GET` | `viewer` | سجل الأحداث الأخير لعمليات الإصلاح التلقائي (`?limit=50`) |
| `/api/healing/reset`  | `POST` | `admin` | رفع الحجر المفروض وإعادة تصفير عدادات التراجع للحاوية |
| `/api/nodes` | `GET` / `POST` / `DELETE` | `viewer` / `admin` | قائمة العقد المسجلة، وإضافة أو إزالة عقد من الشبكة |
| `/api/nodes/heartbeat` | `POST` | `viewer` | استقبال إشارات الحياة والبيانات من الوكلاء البعيدين |
| `/api/cluster/summary` | `GET` | `viewer` | ملخص مؤشرات العنقود (العقد المتصلة، المعالج، الذاكرة، مجموع الحاويات) |
| `/api/cluster/containers` | `GET` | `viewer` | قائمة الحاويات الموحدة الموزعة عبر جميع عقد العنقود (`?node_id=&state=`) |
| `/api/mesh/discovery` | `GET` / `POST` | `viewer` / `admin` | حالة الاكتشاف المحلي عبر UDP وبث إشارة يدوية (`POST {"action":"broadcast"}`) |
